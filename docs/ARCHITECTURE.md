# 架构与对标分析（Architecture）

## 一、本 Skill 要解决的问题

大多数人收集的内容（文章、视频、截图）进了笔记应用就成了"坟场"——只进不出、从不复盘。Matt Wolfe 在《Build A Second Brain That Remembers Everything》中给出的解法：**三支柱 + 实体层 + 定时自动化 + 归档 + 问答写回**，让 AI 持续总结、提取实体、交叉链接、归档，系统随每次摄入变聪明。

本 Skill 用豆包工作复刻这一整套能力，去掉命令行和 API Key 门槛，中文零代码。

## 二、系统组成（全能力）

| 层 | 组件 | 职责 |
|---|---|---|
| 前端 | Obsidian | 本地 Markdown 库、图视图、双括号链接、全文检索 |
| 收集 | 豆包工作对话 | 视频/文章/截图/文件直接喂入，人在环中 |
| 转写 | 飞书妙记 | 视频 → 段落级逐字稿（含时间戳） |
| 加工 | 豆包工作 | 双语对照、总结页、实体提取、自动互链、问答写回、index/log 维护 |
| 归档 | Raw Sources/processed | 处理完的原始文件移入，收件箱保持干净 |
| 复盘 | Journal | 每日复盘 + 近 30 天模式识别 |
| 人脉 | CRM | 联系人笔记 + 关联实体/想法/事件 |
| 自动化 | 豆包工作定时任务 | 每日巡检 index、定时复盘、git 备份 |
| 存储 | Obsidian 本地库 | Raw Sources / Wiki / Journal / CRM 分层，Markdown 明文，用户拥有数据 |

## 三、数据流（摄入链路）

```
输入 → 路由 → [视频: 下载→转音频→妙记转写] / [文章: 抓取] / [截图: OCR提取]
     → 中英双语 / 结构化整理
     → Raw Sources/<日期>-<主题>.md   (收件箱, frontmatter 记来源)
     → Wiki/<主题>.md                (总结页)
     → Wiki/Entities/<实体>.md        (实体页: 人物/公司/工具/想法/主题, 提及记录累积)
     → 自动互链                        (查 index 找相关页, 互相补链接 + 反向引用)
     → Raw Sources/processed/          (原始文件归档)
     → index.md 更新 + log.md 追加
```

## 四、复利回路（为什么"越用越聪明"）

- **摄入复利**：每条内容 → 总结页 + 实体页 + 互链 → 知识网络变密
- **问答复利**：每次提问 → 答案写回 Queries → 下次可复用
- **复盘复利**：每日复盘 → 30 天模式识别 → 长期洞察（"你反复卡在视频选题上"）
- **人脉复利**：CRM 关联实体 → 聊过的工具/公司自动浮现在联系人页

## 五、为什么人在环中（与全自动方案的关键差异）

- **质量把关**：AI 提取的内容由用户确认后再入库，避免"AI 幻觉进知识库"
- **隐私可控**：敏感内容（证照、资产、内部资料）可在入库前拦截
- **学习复利**：入库时的讨论本身就是"原子笔记"式的理解（参见 Zettelkasten 方法）
- **真实优先**：Journal/CRM/实体「提及记录」缺省标「待补充」，不替用户虚构

## 六、扩展方向（v0.4+）

- 周报/月报聚合：从每日复盘自动生成周报
- CRM 提醒：定时任务到期提醒「下次跟进 XX」
- 多库支持：同一 Skill 管理多个 Obsidian 库（工作/个人）
- 竞品监控：定时摄入特定来源（对标 Matt 的 competitive intelligence 用法）
