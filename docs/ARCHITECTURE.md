# 架构与对标分析（Architecture）

## 一、本 Skill 要解决的问题

大多数人收集的内容（文章、视频、截图）进了笔记应用就成了"坟场"——只进不出、从不复盘。Matt Wolfe 在《Build A Second Brain That Remembers Everything》中给出的解法：**三支柱（Wiki + Journal + CRM）+ LLM-Wiki 架构 + 定时自动化**，让 AI 持续总结、交叉链接、归档，系统随每次摄入变聪明。

本 Skill 用豆包工作复刻这一能力，去掉命令行和 API Key 门槛。

## 二、三支柱系统

| 支柱 | 目录 | 职责 | 触发 |
|---|---|---|---|
| Wiki | `Wiki/` | 摄入内容 → 总结页；知识可检索、可互链 | 「整理进知识库」 |
| Journal | `Journal/` | 每日复盘：AI 从 Wiki 挑出与当日最相关内容，形成「今日新知」 | 「今天复盘」 |
| CRM | `CRM/` | 人脉笔记：背景/最近互动/关注点/下次跟进 | 「记录一下 XX」 |

一份 `AGENTS.md` 规则文件同时驱动三支柱（对标 Matt Wolfe 的 agents.md 单一控制文件）。

## 三、系统组成

| 层 | 组件 | 职责 |
|---|---|---|
| 前端 | Obsidian | 本地 Markdown 库、图视图、双括号链接、全文检索 |
| 收集 | 豆包工作对话 | 视频/文章/截图/文件直接喂入，人在环中 |
| 转写 | 飞书妙记 | 视频 → 段落级逐字稿（含时间戳） |
| 加工 | 豆包工作 | 双语对照、结构整理、三支柱页面维护、index/log 更新 |
| 自动化 | 豆包工作定时任务 | 每日巡检 index 一致性、定时生成复盘 |
| 存储 | Obsidian 本地库 | Raw Sources / Wiki / Journal / CRM 分层，Markdown 明文，用户拥有数据 |

## 四、数据流

```
输入 → 路由 → [视频: 下载→转音频→妙记转写] / [文章: 抓取] / [截图: OCR提取]
     → 中英双语 / 结构化整理
     → Raw Sources/<日期>-<主题>.md   (原始存档, frontmatter 记来源)
     → Wiki/<主题>.md                (AI 总结页, 双括号互链)
     → Journal/<日期>-复盘.md         (复盘引用 Wiki 今日新知)
     → CRM/<姓名>.md                 (人脉笔记, 缺省标待补充)
     → index.md 更新                  (页面总数+摘要行)
     → log.md 追加                    (动作/来源/产物)
```

## 五、为什么人在环中（与全自动方案的关键差异）

- **质量把关**：AI 提取的内容由用户确认后再入库，避免"AI 幻觉进知识库"
- **隐私可控**：敏感内容（证照、资产、内部资料）可在入库前拦截
- **学习复利**：入库时的讨论本身就是"原子笔记"式的理解（参见 Zettelkasten 方法）
- **复盘真实**：Journal/CRM 缺省字段标「待补充」，不替用户虚构事实

## 六、扩展方向（v0.3+）

- 定时巡检自动化完善：自动核对 index 与库内文件一致性并生成差异报告
- Journal 智能聚合：每周/每月自动生成复盘周报（从每日复盘聚合）
- CRM 提醒：结合定时任务，到期提醒「下次跟进 XX」
- 多库支持：同一 Skill 管理多个 Obsidian 库（工作/个人）
