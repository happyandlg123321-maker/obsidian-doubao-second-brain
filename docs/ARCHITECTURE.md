# 架构与对标分析（Architecture）

## 一、本 Skill 要解决的问题

大多数人收集的内容（文章、视频、截图）进了笔记应用就成了"坟场"——只进不出、从不复盘。Matt Wolfe 在《Build A Second Brain That Remembers Everything》中给出的解法：**把收集物变成可查询的 wiki，让 AI 每小时自动总结、交叉链接、归档**。

本 Skill 用豆包工作复刻这一能力，去掉命令行和 API Key 门槛。

## 二、系统组成

| 层 | 组件 | 职责 |
|---|---|---|
| 前端 | Obsidian | 本地 Markdown 库、图视图、双括号链接、全文检索 |
| 收集 | 豆包工作对话 | 视频/文章/截图/文件直接喂入，人在环中 |
| 转写 | 飞书妙记 | 视频 → 段落级逐字稿（含时间戳） |
| 加工 | 豆包工作 | 双语对照、结构整理、Wiki 总结、index/log 维护 |
| 存储 | Obsidian 本地库 | Raw Sources / Wiki 分层，Markdown 明文，用户拥有数据 |

## 三、数据流

```
输入 → 路由 → [视频: 下载→转音频→妙记转写] / [文章: 抓取] / [截图: OCR提取]
     → 中英双语 / 结构化整理
     → Raw Sources/<日期>-<主题>.md   (原始存档, frontmatter 记来源)
     → Wiki/<主题>.md                (AI 总结页, 双括号互链)
     → index.md 更新                  (页面总数+摘要行)
     → log.md 追加                    (动作/来源/产物)
```

## 四、为什么人在环中（与全自动方案的关键差异）

- **质量把关**：AI 提取的内容由用户确认后再入库，避免"AI 幻觉进知识库"
- **隐私可控**：敏感内容（证照、资产、内部资料）可在入库前拦截
- **学习复利**：入库时的讨论本身就是"原子笔记"式的理解（参见 Zettelkasten 方法）

## 五、扩展方向

- Journal 层：日记自动从 Wiki 拉取相关建议（对标 Matt Wolfe 的 journal）
- CRM 层：联系人笔记 + 双向链接（对标 Matt Wolfe 的 CRM）
- 定时巡检：定期让豆包工作核对 index 与库内文件一致性
